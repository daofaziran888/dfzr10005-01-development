# 数仓治理与运维平台

面向数据仓库团队的治理与运维一体化平台。覆盖表生命周期管理、存储成本优化、数据热度分析、任务依赖编排、SLA告警、资源弹性调度与数仓健康度评估的完整治理链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 到期清理演练（三页联动裁决）

在「表生命周期管理」页发起，以生命周期策略为主对象，把候选策略、数据保留规则与
回收记录放进同一张联动裁决视图。演练只做模拟裁决，**不会删除或修改任何业务记录**。

裁决优先级（三个页面看到的结论完全一致，统一收敛在 `app/services/drill.py`）：

1. **合规依据优先**：命中生效保留规则「例外清单」的表，一律裁决「延期」；
2. **更长保留期优先**：同一数据集被多条普通规则覆盖时，取保留天数最大的唯一规则
   （天数相同取规则编号靠前者），其保留天数大于策略保留天数时裁决「受限」；
3. 其余数据才允许进入清理演练，裁决「可清理」。

关键机制：

- 每次演练生成不可变批次，冻结当时的策略/保留规则/回收窗口快照与各自版本号；
- 同策略、同输入口径重复发起只复用原批次结论；规则或回收窗口变化后，旧批次按原口径
  留档可追溯，新批次按新版本重新计算；
- 两个管理员并发争抢同一策略时，后到请求被拒绝占用批次（HTTP 409），结果回写审计清单；
- 回收站页显示每条回收记录的来源策略、演练批次与可恢复截止时间；数据保留页显示哪些
  数据集被演练占用；审计页对「演练完成 / 并发拒绝」做醒目标记。

演练接口（前缀 `/api/drills`）：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /candidates` | 联动裁决视图：候选按风险排列，含三类结果与数量、规则与回收明细 |
| `POST /policies/{policy_id}/batches` | 发起演练（同口径复用，冲突返回 409） |
| `GET /batches` | 演练批次历史，可按 `policy_id` 过滤 |
| `GET /{batch_no}` | 单批次冻结结论与快照 |
| `GET /recycle-link` | 回收站联动：来源策略、批次、可恢复截止 |
| `GET /retention-link` | 保留侧联动：被演练占用的数据集与规则意见 |
